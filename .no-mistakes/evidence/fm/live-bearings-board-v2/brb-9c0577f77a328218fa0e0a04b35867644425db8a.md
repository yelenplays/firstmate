## P1: Unanswered old calls bypass the captain limit

Required: at most three things wait on the captain; before adding a fourth, ask which one to park or drop.

Reproduction against the actual CLI in an empty markdown home:

1. Create old-1, old-2, old-3 with `FM_CAPTAIN_HOLD_NOW=2026-09-26T10:00:00Z bin/fm-captain-hold.sh hold <id> --title 'Unanswered old call N' --reason 'Still need a decision' --repo demo`. This uses the script's supported timestamp input to establish twenty-day-old calls; it does not stub the parser, count, mutation backend, or browser.
2. With the current clock, run `bin/fm-captain-hold.sh hold new-fourth --title 'A new fourth call' --reason 'Another decision' --repo demo`.
3. Observe exit 0 and a fourth persisted captain hold. No answer or deferral occurred. The old rows still report held=yes, captain, no hold-until, and no resolution.
4. Compose and build the real board from that home's actual snapshot. It displays only 1/3 “need you”; the three unanswered calls are non-answerable Charted Next rows.

Cause location: bin/fm-captain-wip-lib.sh:30 counts only hold_bucket=live, thereby importing the display's automatic fourteen-day age exclusion into the new hard brake. Count unanswered, unparked captain obligations independently of display aging, and keep those obligations answerable on the board. This contradicts the explicit acceptance criteria even though display aging predates this change.

Evidence: 08-aged-calls-bypass.log, 10-aged-calls-not-counted.png, 10-aged-board.html.
